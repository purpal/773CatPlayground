# Nova 剩餘十關 Boss 差異化規劃

日期：2026-10-30。分析基準：v0.25.0／main `2d80136`。

狀態：本文件保留最初的設計提案；兔子／企鵝已獲授權進入製作，實作與驗證進度見[改版檢查點](nova-rabbit-penguin.md)。無尾熊／水獺已接續製作，見[本批實作](nova-koala-otter.md)；其餘六關仍為提案。本文件只規劃第三款遊戲 Nova；原本第二款遊戲保留既有行為。

本文的 ID 是 `Stages.number`，不是巡迴出場順序。已完成美術為狗狗 ID 2、熊熊 ID 3、卡皮巴拉 ID 4；剩下 ID 5–13 及最終 Boss 老鼠 ID 1，共十關。初始規劃時前三站固定狗狗→熊熊→卡皮巴拉；最新實作改為已完成七關優先、未改五關隨機、老鼠終局。

## 1. 分析結論

最需要調整的是「招式組合與玩家應對方式」，其次才是機體外觀。現有 Boss 普遍使用橫向移動、瞄準突刺、扇形橫掃、環形彈／螺旋彈，在血量門檻換一套武器。只換成不同動物戰機，玩家仍會重複相同走位。

優先重設兔子、企鵝的戰鬥主軸；保留並放大水獺雙體潛航、樹懶局部彈速、浣熊奪取補給、猴子武器模仿、熊貓可破壞補給與滾動、豬豬區域控制等現有特色。無尾熊應把「休眠時的輸出窗口」提升為整場主軸。老鼠已有三段戰，適合做真正的終局要塞展開與核心覺醒。

前三關已建立的辨識基準：

| 已完成 Boss | 實際現行攻擊 | 階段轉換 | 主要應對方式 |
|---|---|---|---|
| 狗狗：武器決鬥型 | 骨刃突刺／橫掃、投出後回收的骨刃、曲線彈、音波環、橫向衝刺撒彈；後段雙光束向外張開 | 35% 卸武器；一般階段門檻另為 60%／25% | 讀方向、躲掃擊，利用雙光束中央通道 |
| 熊熊：重火力壓制型 | 全幅落彈、重擊環、鑽頭往返橫掃、蜂巢、螺旋彈；後段多道爪擊疊落彈 | 25% 卸鑽頭並進入爪擊組合 | 在彈雨間找空隙，判斷掃擊射程與爪擊扇區 |
| 卡皮巴拉：增裝砲艦型 | 慢速泡泡、拋物線橘子彈、蒸氣環；後段長水柱橫掃、雙柱交叉、曲線飛彈 | 50% 增裝；25% 配件掉落，20% 才換最後表情 | 提早移往掃射安全側，在交叉水柱間走位 |

### 現有重複的程式證據

- 企鵝 `cryoSweep` 與卡皮巴拉 `waterJet` 都是 0.9 秒預告、1.8 秒有效、60°/秒角速度參數、長度 1700 的同類橫掃；換元素並沒有換解法。`sweep` 是角速度，不能把參數值直接當整段總角度。
- 兔子 `drillSweep`、無尾熊 `bladeSweep`、熊貓 `staffSweep`、樹懶 `jetSweep`、猴子 `ruyiSweep`、豬豬 `baguetteSweep` 共用非常接近的「從玩家另一側開始，預告後掃過並補環形彈」模板。
- 多位 Boss 的突刺都是開招及約 1.3 秒時各一次，搭配相似的扇形／圓環補彈。
- 所有 Boss 都繼承 60%／25% 的一般階段門檻，以及 `breakAt` 的 `DISARM` 或 `ARMOR` 邏輯。`broken` 同時代表「已卸甲」或「已增裝」，不足以表達多形態機體。
- 但現有系統並非只有卸甲／增裝：老鼠已在 30% 呼叫 `transform()` 第二次覺醒；水獺有隱藏、不可受傷的潛水狀態；熊貓有獨立滾動路徑；這些可作為後續擴充基礎。

## 2. 剩餘關卡與前三關的相似度

以下為**人工定性評估**，不是玩家測試結果或計算百分比。比較移動方式、主要危險區形狀、轉階段規則、攻擊來源數量，以及玩家是否需要做新的判斷。高＝主要循環和解法大幅重疊；中＝共用多個招式，但有顯著不同機制；低＝主要決策已不同，仍可能共用補彈。

### 5：兔子——跳躍與落點誘導

- **保留：** 原本跳躍／落地反饋、兔耳輪廓、快速機動性。
- **前段：** 輪式車在三條上半場路線換道；雷達鎖定玩家當下位置，顯示兩段跳的落點與順序。落點一經鎖定不再追蹤玩家。
- **40% 後：** 輪組折成雙足，跳躍從短距離換道變成前後突進；落地釋放有缺口的衝擊扇區，隨後約 1.2 秒膝部散熱窗口，可集中輸出。
- **刪減：** 鑽頭長距離橫掃、雙突刺、全畫面隨機落彈。彈幕只用來提示走位，避免搶走跳躍的主角地位。
- **與熊貓區別：** 兔子是離散的「鎖定→離地→落地」，熊貓是連續、可預測的反彈移動。
- **新增工作：** 跳躍危險區與影子同步、落點鎖定、落地碰撞啟用時點、機甲形態及弱點。現有跳躍目前只是上半場橫移，不能直接視為完成。
- **專屬素材：** 車形／機甲形、輪腿展開中間態、推進跳躍、落地姿態、耳型雷達、倒數落點圈、膝部散熱。

### 6：企鵝——封鎖通道與破冰

- **保留：** 停住後重新啟動的冰彈，但限作次要壓力。
- **前段：** 破冰艦先標出兩條結冰帶，依次形成防空冰晶屏障；船艏破冰脈衝打開缺口，玩家讀取缺口位置後通過。艦砲採左右舷輪射，不使用長水柱式掃擊。
- **55% 後：** 船艏分成雙體，展開冰障佈設器；安全通道由直線改為前後錯位。每輪結冰後必有破冰窗口，後段增加順序變化，不同時封閉所有通道。
- **刪減：** `cryoSweep`／`cryoShot` 作為主招、沿上半場來回滑行撒一排冰彈。
- **與樹懶區別：** 企鵝改變「哪裡能通過」；樹懶改變「何時能通過」。企鵝不再發展大範圍時間暫停。
- **新增工作：** 可預告、可破壞的冰障、通道可達性檢查、雙船體砲口定位。海面冰層本身是背景，傷害來自清楚可見的防空冰晶投射。
- **專屬素材：** 完整破冰艦、雙體平台、分艏過程、船舷砲塔、冰障成形／破裂、艏部破冰波、尾流。

### 7：無尾熊——休眠充能與弱點取捨

- **保留：** 休眠時承傷 ×2、可打破的蓄能物，重製為核心散熱艙與外部電容。
- **前段：** 懸吊母艦約每 8–10 秒開艙一次，窗口約 2–3 秒。玩家可直接打脆弱核心，或拆電容避免下一輪高壓放電；時間不足時要取捨。
- **30% 後：** 母艦降下多足固定在上半場，兩側電容交替充能；窗口由中央變成單側，但本體依然可受普通傷害，不要求長時間等待才能打。
- **刪減：** 葉刃橫掃／突刺與追玩家俯衝。落地只用於一次形態轉換，不變成另一隻跳躍 Boss。
- **與熊貓區別：** 無尾熊是「現在輸出或解除下一招」；熊貓是「阻止補給與維持持續輸出」。
- **新增工作：** 可破壞電容與開艙狀態連動、兩側弱點顯示、轉換時支架定位。現有泡泡爆裂可作事件骨架。
- **專屬素材：** 懸吊艦、展足平台、開／閉艙、充能電容與破損狀態、錨足、能量引線、過載脈衝。

### 8：水獺——雙體協同與合體

- **保留：** 左右雙實體、共用生命、輪流射擊與有水面預告的潛航換位。
- **前段：** 左艇排魚雷通道，右艇投可擊破聲納浮標，下一輪互換；兩艇不是同時鏡像發射相同彈幕。潛航時保留航跡與上浮位置提示。
- **45% 後：** 兩艇對接為雙體戰艦，中央發射器運作時一側艙門打開；玩家移到暴露的一側輸出。兩側連接臂先亮線，再短暫形成防空聲納屏障。
- **刪減：** 雙錘交叉與常態雙環形彈。合體不能只是兩張圖重疊。
- **與浣熊區別：** 水獺兩艘都是真實目標；浣熊要辨真假。水獺潛航有空間航跡，不用全息消失特效。
- **新增工作：** 合體座標、同一生命池的傷害去重、左右舷窗口、浮標生命週期；總體不可受傷時間建議控制在戰鬥的 15% 以內。
- **專屬素材：** 姊妹艇各一套、潛航／上浮、對接中間態、合體戰艦、舷門、連接臂、聲納浮標、雙駕駛員通訊頭像。

### 9：熊貓——供能與球形反彈

- **保留：** 可破壞竹筍改成供能柱；原本最多三次、每次 3% 回血及補給時脆弱的設計，可作初版平衡基準；保留已有反彈預告路徑。
- **前段：** 履帶車投放供能柱，柱間交替接通短時電網。玩家先拆節點打開射線，再在充能時打本體。
- **40% 後：** 頭部與履帶收進球殼，沿預告路徑反彈兩至三次，然後停轉開核心；路線鎖定後不跟著玩家修正。
- **刪減：** 竹棍突刺、橫掃；滾動期間減少隨機彈，讓玩家能讀路線。供能柱死亡立即撤銷相關電網。
- **新增工作：** 球形與履帶狀態真正切換、節點連線與供能互動；沿用 `RollBall` 同一套數學生成預告及實際路徑。
- **專屬素材：** 履帶車、半收納、完整球殼、開核心球體、滾動光帶、供能柱、電網預告／有效狀態。

### 10：樹懶——局部時序反轉

- **保留：** 只改變敵彈的局部流速，0.3／1.7 倍可作初版基準；玩家移動、觸控和遊戲時鐘不變慢。
- **前段：** 纜索運輸艦把彈群蓄在環形力場內，依扇區順序放行；場邊緣有流向箭頭及釋放倒數，玩家讀的是脫離力場後的速度。
- **35% 後：** 脫離纜索，艙段展成環形飛行器；力場反轉為圈內加速，慢區／快區交替啟用。第一版只保留一個主力場，避免多圈疊加難以判讀。
- **刪減：** 火箭火焰橫掃、常態高速衝撞。機體移動以讓玩家能看清場界為優先。
- **新增工作：** 分批放行、流速變化預告、邊界平滑過渡；不是直接把所有積存彈瞬間加速壓向玩家。
- **專屬素材：** 吊掛運輸艦、展環中間態、環形機體、環段開合、慢／快場邊框、箭頭與倒數、釋放閘門。

### 11：浣熊——戰利品與真假辨識

- **保留：** 抓取場上補給；沒有補給時命中玩家可偷一份核心超載；打破戰利品艙返還並進入短暫脆弱。既有背袋每 12 秒重生及 3 秒脆弱可作基準。
- **前段：** 偽裝貨運車在屋頂運輸軌道移動，以磁索搶奪補給；被鎖定物有明確連線，不憑空扣除玩家資源。
- **50% 後：** 車殼翻開為投影天線，真車與兩個全息假車換位。真車具實際車轍／尾氣及持續的貨艙信標；假體顯示掃描線，擊中可快速消散。
- **刪減：** 抓鉤重複雙突刺與水花圓環。新版後段仍保留可辨識的搶奪機會，避免進入分身階段後戰利品玩法消失。
- **與猴子區別：** 浣熊的假體用來辨識；猴子的回放裝置全部是真實攻擊源，沒有真假題。
- **新增工作：** 前後形態都能管理戰利品、死亡時保證返還未取回補給、假體識別不依賴顏色或陰影單一線索。返還事件須防止重複發獎。
- **專屬素材：** 貨運偽裝車、電戰展開形、戰利品艙空／滿／破裂、磁索、全息假體、信標、真實輪跡、駕駛員。

### 12：猴子——適應武器與圖騰覺醒

- **保留：** 依主武器 SPREAD／FOCUS／SPECIAL 與橘貓／黑貓選擇模仿招式。
- **前段：** 可變翼偵察機掃描約 1.2 秒，顯示「擴散／聚束／重力／震波」圖示，之後按掃描當下的武器出招；招式中途不因玩家換武器偷改答案。
- **30% 後：** 翼片折成猿形機甲雙臂、尾部展開平衡環；保留相同武器語言，增加不同發射位置，讓先前學到的規則仍有效。
- **25% 覺醒：** 古代猿形圖騰從機甲浮現，出現一個可摧毀的回放節點，延遲重播上一招的較弱版本。覺醒改變攻擊時序，不只是換色或加大傷害。
- **刪減：** 通用伸縮棍橫掃／雙突刺，以及看起來和浣熊相似的真假分身。低血量若一次跨過 30%／25%，變形與覺醒合併演出，避免連續等待。
- **新增工作：** 掃描快照、可見預告、回放佇列、節點被破壞後取消回放。三種主武器及兩隻貓均需覆蓋。
- **專屬素材：** 偵察翼形、變形過程、猿形機甲、覺醒機甲、猿圖騰透明層、四種掃描圖示、回放節點與提示。

### 13：豬豬——採掘地形與區域規劃

- **保留：** 預告後爆出的地雷與暫時減速區，但從泥巴笑點改為採掘設備的戰術區控。
- **前段：** 採掘車標出鑽孔，一個鎖定玩家舊位置、其餘按固定區塊佈置；鑽孔先噴警示塵，再射出防空碎片。冷卻孔留下可見牽引場，明確表示會降低飛行器移速。
- **45% 後：** 六足展開固定，鑽孔按一→二→三順序串聯爆破，兩側各有可破壞的鑽探臂；拆一側可取消該側下一輪，不靠全面清彈解決。
- **刪減：** 法棍突刺／橫掃、可頌迴力鏢、橫向打滾撒彈。減速不能再配合難以迴避的追蹤橫掃。
- **與老鼠區別：** 豬豬讓玩家誘導落點並管理持續區域；老鼠採已編排的移動閘門與路線題。
- **新增工作：** 區域佔用上限與連通逃生路徑；第一版減速建議由現有 0.5 倍放寬到 0.7 倍，且不疊乘。大型機體始終位於上半場，環境不需可破壞地形系統。
- **專屬素材：** 採掘車、展足平台、左右鑽臂與破壞狀態、鑽孔預告／爆發／冷卻、牽引場、足部固定效果。

### 1：老鼠——移動要塞、分節與核心機神

- **保留：** 60%／30% 三段結構、缺口牆、預告跑道、觸發陷阱；作為終局綜合考驗。
- **100–60%：** 磁軌要塞在上半場沿軌道行進，車廂砲塔依序開火，防空閘門由上而下推進；拆砲塔可以擴大一個缺口。
- **60–30%：** 各節車廂分離到左右側，形成移動攻擊源；預告後依次推出封鎖列，中央核心可持續攻擊。磁軌地雷只作短期封路，不在缺口內無預告生成。
- **30% 以下：** 鼠形核心機神脫離車廂，王冠展成圖騰環；以脈衝閘門及換位核心為主。殘餘車廂只作背景或已解除的障礙，不把前三段所有招式一起堆滿。
- **刪減：** 瑞士刀雙突刺／交叉、長時間隨機熔融彈雨。終局透過場面與規則變化增加強度，而非單純增加彈量。
- **與猴子區別：** 猴子是「讀玩家武器並延遲回放」；老鼠是「場地結構瓦解後追打核心」，不再次模仿玩家。
- **新增工作：** 多節目標、部件死亡影響通道、轉形後碰撞範圍更新、跨門檻事件序列。這關工程量最大，安排最後製作。
- **專屬素材：** 要塞本體、不同車廂、砲塔、分節連接器、脫離核心、鼠形機神、王冠圖騰環、閘門、軌道陷阱、終局崩解效果。

## 4. 共同美術與戰鬥規則

### 空、陸、海載具如何共存

- 維持現有俯視 2D 射擊視角。陸地車有輪跡、足跡與貼地陰影；海艦有尾流和潛航波紋；飛行器有高度陰影與尾焰。背景表達所在地與行進方向。
- 玩家機體維持低空戰鬥抽象；陸地／海面武器以防空砲、向上能量幕、碎片或牽引場威脅玩家。純地面泥巴、冰面或車轍不直接傷害飛機。
- 不新增完整 3D 高度、地形物理或另一套操作方式。形態造成碰撞變化時，在 2D 判定明確啟閉；視覺離場不等於仍有隱形碰撞。
- 使用輪廓表達動物特徵：耳型感測器、口鼻形艏部、爪型支架、尾部穩定器；駕駛員肖像保留動物身份。避免每台都靠貼上動物頭才有辨識度。

### 變化種類的分工

- **卸武器／增裝：** 前三關已負責示範，後續只作局部配件損壞，不再每關當主轉折。
- **機械變形：** 兔子、企鵝、無尾熊、熊貓、樹懶、豬豬，改變承載結構與運動方式。
- **分離／合體：** 水獺合體、老鼠分節；可攻擊部件與火力來源同步變化。
- **偽裝／投影：** 浣熊，改變資訊判讀。
- **變身／覺醒：** 猴子、最終老鼠，機體之外出現古代圖騰並帶來新規則。控制使用次數，保留終局層次。

### 公平性與節奏（初版目標，尚待實測）

- 每位 Boss 一個主機制、最多兩個輔助壓力；每個形態至少有兩輪能清楚學習的招式循環。
- 新危險招首見約 1.0–1.2 秒預告，重複招可調至約 0.75–0.9 秒；具體下限要用最慢機體到安全區的時間驗證，不能一律按巡迴倍率壓縮。
- 危險區以紅橙實線／填充、預告以虛線／倒數、弱點以破損輪廓與亮框區分；不只依賴顏色。特效遮蔽不能大過判定提示。
- 機械轉形約 1.2–1.8 秒，覺醒約 2 秒；舊招先收束再換形態。不得在新形態已顯示時繼續保留舊武器的不可見攻擊。
- 大招結束有約 1–2 秒追打窗口；移動 Boss 應有停留時間，避免一直離開玩家可攻擊範圍。
- 轉形／回血均不能重複觸發已完成事件。一次高傷害跨多個血量門檻，要合併演出或依序完成，不重複掉補給、重複無敵或復活部件。
- 任何封路組合至少留一條可達退路；以實際機體判定、移速、短螢幕可用高度驗證，不能只看截圖覺得有縫。
- 每關前半段小怪先教學主題：兔子教落點圈、企鵝教冰障缺口、水獺教左右火力、浣熊教貨艙信標等，再由 Boss 組合運用。

## 5. 程式落地規劃

### 可沿用的能力

現有 `Attack` 排程、`Laser` 預告與判定、曲線／加速度／停滯彈、`Enemy.damageTarget` 共血、`damageScale` 脆弱窗口、隱藏／不可受傷、可擊破子目標、`bulletTimeScale` 都能重用。Nova 的素材路由與圖集也已能承接新圖。

但這不是純素材替換就能完成：目前 `NovaSector` 明確只負責美術，`World.spawnBoss()` 仍使用共同的 `stage.createBoss()`。直接修改原有十個 Boss，會改到第二款遊戲。

### 建議以小範圍擴充隔離 Nova

1. 在 `World` 建立 Boss 的入口加入可選工廠，預設維持 `stage.createBoss()`；只有 Nova 傳入新工廠。不要全域替換 `Stages` 中的 Boss 或改存檔 ID。
2. 新行為放在 Nova 專用 Boss 類別，沿用共同 `Boss` 基礎能力。現有具體 Boss 類別預設不能繼承，不能假設直接 override 幾個招式即可完成。
3. 為基底新增可覆寫的「形態轉換策略」鉤子，預設執行原本 `broken / breakAt / phase` 路徑；Nova 新 Boss 才使用獨立 `formId`、`transitionState`、已完成事件集合。避免以假的卸甲門檻來冒充變形。
4. 將 Nova 的形態、傷損、武器裝備與動畫分開讀取；不能再只靠 `mood` 或 `broken` 選 sprite。`NovaSector.body` 及預覽入口需要承接形態資訊。
5. 轉形事件集中處理舊攻擊收束、短暫無敵、部件重定位、音效與碰撞啟閉。現有 `clearBullets()` 會清彈與雷射，但不會移除所有以 `Enemy` 表示的陷阱、投射物或召喚物；需為 Nova 子物件記錄 owner／存續規則，避免轉形後殘留危險。
6. `WorldPainter` 與 `World` 現有若干 `is OtterBoss` 等特例；新雙體／多節 Boss 應走 Nova 部件與呈現介面，不能假設換類別後原有型別判斷仍會生效。死亡清場、共血與部件獎勵也一併檢查。
7. 有新形態時先補灰盒招式與判定，再定稿美術；不先生成大量圖片後遷就錯誤的關節位置。

### 素材交付規格

- 每關先做「全形態同頁設計板」供確認：正俯視戰鬥姿態、45° 預覽、輪廓比例、變形對應關係。轉形前後要看得出同一台機體。
- 每個主要形態至少一張乾淨本體、一張必要的受損／開艙狀態；機械轉換依關節需求準備約 3–5 個中間態或可動部件。這是結構動畫，不再使用選機旋轉圖組。
- 本體、可動武器、弱點、尾焰／尾流、圖騰、攻擊預告、有效攻擊及消散分層；manifest 記錄 pivot、砲口、關節、弱點與碰撞參考點。
- 同一形態圖固定畫布與基準點，不靠透明邊界裁切決定縮放，避免開艙或失去配件後整台突然變大。
- 每關配套完整：背景、小怪、精英、Boss／部件、子彈、特殊攻擊、駕駛員肖像與新過關對話。通用升級道具沿用目前科技風設計，補充專屬補給艙外觀即可。
- 對話回應該關玩法，例如承認被看穿投影、被拆斷供能或失去時序控制，避免每關只說「核心過載」。

## 6. 製作順序與驗收

| 批次 | 關卡 | 原因／交付重點 |
|---|---|---|
| 0 | Nova 隔離入口＋形態狀態最小原型 | 原版回歸先確立；用兔子兩形態驗證碰撞、動畫、跨門檻 |
| 1 | 兔子＋企鵝 | 相似度最高，先建立陸地／海上輪廓與兩種不同走位題 |
| 2 | 熊貓＋無尾熊 | 重用可破壞節點／脆弱窗口，但分別驗證路線與輸出取捨 |
| 3 | 浣熊＋豬豬 | 驗證資源返還、真假辨識、持續區域及退路 |
| 4 | 水獺＋樹懶 | 共血合體與時序控制較複雜，需額外碰撞、節奏測試 |
| 5 | 猴子＋老鼠 | 利用前面成熟的形態、部件和預告能力，製作模仿與終局多段戰 |

每批完成「灰盒可玩→形態設計板→完整素材→程式整合→驗收」；製作順序不等於強制改巡迴排序。尚未確認的新方案不直接替換已發布前三關。

驗收清單：

- 固定種子模擬完整招式輪替、門檻前後、一次跨多門檻、變形中擊殺、部件先死、暫停／重試，避免狀態卡住。
- 用橘貓與黑貓的移速／命中範圍驗證退路；低火力仍能過關，高火力不會跳過狀態後卡死。
- 雙體／多部件受同一次穿透或範圍攻擊時，按設計去重，不因新增圖層無意倍增傷害；死亡只發一次分數／補給。
- 樹懶只改敵彈流速；浣熊返還資源不遺失或重複；熊貓補給不造成階段倒退；猴子掃描快照與回放一致。
- GitHub Actions runner 錄製或連續截取完整主招與轉形，不只抓門檻後一張靜態畫面；檢查一般／短螢幕、預告與實際判定、擊破與對話。
- 原版第二款的 Boss 工廠、階段門檻與既有測試結果維持；Nova 前三關跑回歸。
- 最後人工確認：不看名稱與顏色，也能從輪廓與招式判斷對手；每關玩家能用不同的一句話描述應對方法。
